# Single-cycle processor

We begin by piecing together a single-cycle processor, i.e, a processor where a single instruction takes one clock cycle to execute. We'll start by defining some of the memories we'll need: instruction memory, a 32x32 register file and data memory. Oh, and we'll discuss the program counter here too.

## Program Counter

A good place to start is the program counter. We'll cover how RISC-V addressing works here. We'll start off with the storage element of the program counter here, and expand the PC to its complete form later on.

This is pretty simple. We want our program counter to give us a new address every clock cycle, and we want a way to control the next instruction address (we're not necessarily always incrementing by +4, jumps etc can override this).

This behaviour can be modelled incredibly simply (and flexibly) with a D-Flip-Flop (DFF) as so:

<SideBySide>
<Side caption="The program counter: a 32-bit D flip-flop that latches pc_next on every rising clock edge.">

```verilog
module program_counter(
  input logic clk,
  input logic [31:0] pc_next,
  output logic [31:0] pc
);

  always_ff @( posedge clk ) begin
    pc <= pc_next;
  end

endmodule
```

</Side>
<Side caption="Its cocotb test. Drive pc_next, wait one rising edge, then check pc took the value.">

```python
@cocotb.test
async def test_pc_dff(dut):
    instruction = 0xFFC4A303 # lw x6 -4(x9)
    cocotb.start_soon(
      Clock(dut.clk, 10, unit="ns").start()
    )

    dut.pc_next.value = instruction

    await RisingEdge(dut.clk)
    await Timer(1, unit="ns")

    assert dut.pc.value == instruction
```

</Side>
</SideBySide>

We'll expand this later to include incrementing with an ALU/specifying a specific instruction to jump to.

I mentioned earlier that the PC increments by `+4`. Why? Those who've studied computer architecture before will know the program counter stores the address of the instruction currently being executed (we'll take `pc` to be the "stored" port here).
So, why not `+1`? This comes down to how RISC-V is addressed.

RISC-V is byte-addressed rather than word-addressed. This is the case for most modern ISAs as far as I'm aware. Being byte-addressed has many benefits in the modern world that I won't
go into too much detail here about, but a few to take note of: the ISA itself has granular load and store instructions such as `lb` and `sb` so it helps to address to bytes rather than full 32-bit
words. A lot of languages today also assume a byte-addressed model - like C for example: `sizeof(char) = 1 byte`.

Being byte-addressed means to get the next address, simply incrementing by `+1` won't get us our next instruction. We'll need to increment by 32-bits, or 4 bytes, hence the `+4`.

## Instruction Memory

The instruction memory is purely combinational - it combinationally reads a 32-bit instruction at address `A` onto the read data output `RD`. Let's look at how we might implement this. First, defining our ports and some memory:

<SideBySide>
<Side caption="ins_mem: 64 words of 32 bits, read combinationally at A.">

```verilog
module ins_mem (
  input logic [31:0] A,
  output logic [31:0] RD
);

  logic [31:0] mem [0:63];

  assign RD = mem[A[7:2]];

endmodule
```

</Side>

> [!NOTE]
> The keen-eyed reader will notice something interesting. A 32-bit address implies $2^{32}$ possible 32-bit words of instruction memory. This is gigabytes of instruction memory, and is obviously absurd,
> hence, we restrict our `mem` array to simply 64 (`[0:63]`) words of 32-bit (`[31:0]`) instructions. $2^{32}$ is simply the upper-bound of what RISC-V could theoretically support.

RISC-V being byte-addressed means that address `A` doesn't point to a full 32-bit instruction word. So... what does it point to? and how do we access our entire instruction?

Let's look at some examples first.

- `A = 0x0` - Ok this seems pretty easy. We simply drive `RD` to `mem[0]`.
- `A = 0x4` - Erm. Woah, we just skipped 3 instructions?
- `A = 0x8` - Okay. Now I'm confused!

Like I said before, the address `A` here actually points to the lowest-significant byte of our instruction. If we simply used `A` is the address in `mem`, we'd miss out many instructions.

<SideBySide reverse>
<div>

If you haven't noticed, we can effectively get the right "row" in `mem` by simply dividing `A` by 4, i.e `instruction = mem[A/2]`. Cool we have a rule to follow, but how does this translate to hardware?
Simple! Remember that shifting right is effectively a division by 2! So we just shift `A` to the right by 2 bits.

`A` shifted right gives us `A[31:2]`, but our `mem` size is just 64 words, so we'll keep only the bottom 6 bits ($2^6 = 64$), hence `A[7:2]`.
